센서 데이터 전송 규격 (2026-10-21, 초안 v0.1)
================================================
하드웨어 담당 → 소프트웨어 담당 공유용

지금 상황
  라즈베리파이가 1분마다 센서값을 CSV로 저장하고 있고, 일주일치가 쌓였습니다.
  이 데이터를 웹서비스로 자동 전송하려고 합니다.
  받는 쪽 예제 서버(261021_api_server.py)도 같이 보냅니다.
  그대로 써도 되고, 이미 만든 코드가 있으면 아래 규격만 맞춰 주세요.


1. 라즈베리파이가 보내는 방법
------------------------------
POST  <주소>/api/readings
헤더  Content-Type: application/json
      X-API-Key: CHANGE_ME        ← 양쪽이 같은 값이면 됩니다

본문 (예시)
{
  "device_id": "pi-01",
  "readings": [
    {
      "time": "2026-10-21T14:30:00",
      "soil1": 576, "soil2": 567, "soil3": 570, "soil4": 563,
      "light": 64,
      "temp": 29.1, "hum": 48.0,
      "n_samples": 1,
      "note": ""
    }
  ]
}

- readings 는 배열입니다. 한 번에 여러 줄이 올 수 있습니다.
  (인터넷이 끊겼다 돌아오면 밀린 것을 최대 200줄씩 몰아서 보냅니다)
- 처음 한 번은 일주일치 약 10,000줄이 나눠서 올라갑니다.


2. 각 칸의 뜻
-------------
time        측정 시각. 라즈베리파이 시계 기준. ISO 형식 문자열
soil1~4     화분 1~4 토양수분. 0~1023 원래 값. **클수록 건조**
light       조도. 0~1023. 클수록 밝음
            (조도센서를 BH1750으로 바꾸면 단위가 lux로 바뀝니다. 바꾸면 알려줄게요)
temp        온도 °C
hum         습도 %
n_samples   그 1분에 받은 줄 수. 0이면 그 시간에 데이터를 못 받았다는 뜻
note        문제 표시. "" / "no_data" / "dht_fail" / "bad_lines=3"

빈 값 주의
  temp, hum 은 센서 읽기 실패 시 null 로 옵니다. soil/light 도 null 일 수 있습니다.
  null 이 와도 서버가 거절하지 말고 그대로 저장해 주세요.
  (데이터가 빠진 구간도 기록으로 남겨야 나중에 설명할 수 있습니다)


3. 중복 처리 (중요)
-------------------
같은 device_id + time 이 두 번 올 수 있습니다.
(전송 도중 끊기면 라즈베리파이가 다시 보냅니다)

→ (device_id, time) 을 기본키로 두고 덮어쓰기(UPSERT) 해 주세요.
  예제 서버는 INSERT OR REPLACE 로 처리하고 있습니다.


4. 응답
-------
성공: 200 과 함께 아무 JSON (예: {"saved": 200})
실패: 4xx/5xx
      → 라즈베리파이는 기록을 앞으로 넘기지 않고, 다음 번에 그 줄부터 다시 보냅니다.
        데이터가 사라지지 않으니 서버가 잠깐 꺼져도 괜찮습니다.


5. 조회용 주소 (예제 서버에 이미 있음)
---------------------------------------
GET /api/latest                      가장 최근 한 줄 → 화면 상단 '현재 상태'
GET /api/readings?limit=1000         최근 1000줄 → 그래프
GET /api/readings?since=2026-10-15T00:00:00
GET /api/stats                       며칠치 쌓였는지 요약
GET /health                          서버 확인


6. 값을 %로 바꾸는 식 (토양수분)
--------------------------------
화면에 "576"을 그대로 보여주면 사용자가 이해할 수 없으므로 %로 바꿉니다.
센서마다 숫자가 다릅니다.

  수분% = (공기값 - 측정값) / (공기값 - 물속값) × 100     (0~100으로 자름)

    A1(화분1): (590 - raw) / 321 × 100
    A2(화분2): (578 - raw) / 326 × 100
    A3(화분3): (577 - raw) / 329 × 100
    A3(화분4): (571 - raw) / 355 × 100     ★ 2026-11-01 재보정

  ※ 화분1~3: 임시 보정값 (브레드보드 상태, 2026-10-11~12 측정, 공기/물속 기준)
  ※ 화분4: 2026-11-01 재보정. 흙 기준 — 마른 흙 571, 흠뻑 물 준 직후 216
           (같은 날 오전 값 259 는 물을 덜 줬거나 센서를 다시 꽂기 전 값이라 버림.
            물 준 뒤 1~2시간 안 최저값을 보고 더 낮으면 그 값으로 바꿀 예정)
           (이전 값: 공기 576, 물속 251 → (576 - raw) / 325 × 100)
           흙 기준이라 "물 준 직후 = 100%", "마른 흙 = 0%" 로 읽힙니다.
  ※ 10/21 이후 핀이 바뀌어 화분1~4 = A0~A3 입니다. (위 화분1~3 의 A1~A3 표기는 옛 핀)
  ※ 납땜 후 다시 재서 숫자를 바꿀 예정입니다. 그때 알려줄게요.
  ※ 코드에 숫자를 직접 적지 말고 설정값으로 빼 두면 나중에 바꾸기 편합니다.


7. 내가 알아야 할 것
---------------------
아래 두 가지만 알려주면 라즈베리파이 쪽 설정을 맞추고 바로 전송 시작합니다.

  (1) 주소:  http://___________________/api/readings
  (2) API 키를 바꿀 거면 바꿀 값

웹서비스가 아직 배포 전이면, 조원 노트북에서 예제 서버를 띄우고
그 노트북 IP 를 알려줘도 됩니다. 같은 와이파이면 전송됩니다.
