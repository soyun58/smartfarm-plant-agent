[공유] 조도센서를 바꿉니다 — 단위가 바뀌어요 (2026-10-21)
==========================================================
하드웨어 담당 → 소프트웨어 담당

한 줄 요약
  조도센서를 CdS(아날로그) → BH1750(디지털)로 바꿉니다.
  light 칸의 단위가 "0~1023 상대값" 에서 "lux(럭스)" 로 바뀝니다.


1. 무엇이 바뀌나
-----------------
                     바꾸기 전            바꾼 뒤
  센서               CdS                 BH1750
  light 값           0 ~ 1023            lux (실제 밝기 단위)
  값의 종류          정수                 소수 가능 (예: 3421.7)
  밤에 찍히던 값     60 ~ 170 정도        수십 lux
  밝은 실내          900 대               수백 ~ 수천 lux

  나머지 칸(soil1~4, temp, hum, n_samples, note)은 그대로입니다.
  CSV 와 API 형식도 그대로입니다. 칸 이름도 light 그대로예요.


2. 교체 날짜
-------------
  교체 시각 : 2026-10-__  __:__      ← 바꾸고 나서 채워 넣겠습니다

  이 시각을 기준으로 앞뒤 데이터의 단위가 다릅니다.
  그래프를 그릴 때 이 시점을 세로선으로 표시하거나,
  교체 이후 데이터만 쓰는 편이 설명하기 쉽습니다.


3. 코드에서 고쳐야 할 것
-------------------------
  (1) light 를 정수로 읽는 부분이 있으면 소수로 바꿔 주세요.
      "3421.7" 을 정수로 바꾸려 하면 오류가 납니다.

  (2) DB 컬럼 타입도 정수(INTEGER)면 소수(REAL/FLOAT)로 바꿔 주세요.
      예제 서버(261021_api_server.py)는 이미 REAL 로 바꿔 두었습니다.

  (3) 화면에 단위를 "lux" 로 표시해 주세요.
      예: "조도 3,421 lux"
      예전처럼 "조도 820" 으로 두면 사용자가 의미를 알 수 없습니다.

  (4) 값의 범위 검사를 하고 있다면 상한을 올려 주세요.
      BH1750 은 수만 단위까지 올라갑니다. [정확한 최대값은 데이터시트 확인 필요 — 미확인]


4. 왜 바꾸나 (발표에서 쓸 이유)
--------------------------------
  - lux 는 실제 단위라서 사용자와 심사위원에게 설명하기 쉽습니다.
  - 디지털이라 선이 길어져도 값이 흔들리지 않습니다. 센서를 잎 높이까지
    올려야 하는데, CdS 는 그때 잡음에 약했습니다.
  - CdS 는 개체마다 값이 달라 보정이 필요하지만 BH1750 은 필요 없습니다.

  발표 때 "처음엔 CdS로 시작했지만 값이 상대적이라 설명이 어렵고
  긴 배선에 약해서 디지털 센서로 바꿨다" 고 말하면 설계 근거가 됩니다.


5. 알아두면 좋은 한계
----------------------
  lux 는 사람 눈 기준의 밝기 단위입니다.
  식물의 광합성에 쓰이는 빛의 양은 PAR(광합성유효복사) 이라는 다른 기준으로 재며,
  lux 가 높다고 식물에 좋은 빛이라고 단정할 수는 없습니다.
  전용 PAR 센서는 가격대가 달라 이번 과제에서는 쓰지 않습니다. [가격 미확인]

  챗봇 답변에서 "빛이 충분하다/부족하다" 를 말할 때는
  이 한계를 염두에 두고 표현을 정하면 좋겠습니다.


6. 식물 기준값
---------------
  방울토마토에게 몇 lux 가 적당한지는 아직 조사하지 않았습니다. [미확인]
  출처가 있는 자료를 찾으면 공유하겠습니다.
  그 전까지는 "적정/부족/과잉" 판정 기준을 코드에 박아두지 말고
  설정값으로 빼 두는 편이 좋습니다.
